# BT 客户端

基于 **libtorrent 2.x** 引擎 + **Tauri 2** 壳 + **React / TypeScript** 前端的 BT（BitTorrent）下载客户端，Windows 优先。

引擎用 C++ 封装成 HTTP 服务，前端通过 Tauri 壳发现引擎端点并驱动，实现「引擎崩溃可恢复、壳强杀可接管、任务加即落盘」的健壮性目标。

> **状态**：代码与自动化判据已完成（86 条验收标准全绿）。剩 5 条「现场验收」项需要干净机器冷启动或换网络复测。

## 架构

```
┌─────────────────────────────────────────────┐
│  Tauri 2 壳 (btclient-shell)                │
│  ├─ 发现引擎端点 (engine.endpoint.json)      │
│  ├─ 托管 React 前端 (tauri.localhost)        │
│  └─ 生命周期：接管孤儿引擎 / 关窗语义        │
├─────────────────────────────────────────────┤
│  React + TypeScript 前端                     │
│  ├─ 任务列表 / 状态词表 / 实时轮询           │
│  └─ 磁力 + .torrent + 拖拽 三入口添加        │
├─────────────────────────────────────────────┤
│  C++ 引擎 (engine)                          │
│  ├─ libtorrent 2.x 封装                     │
│  ├─ HTTP 服务 (127.0.0.1:<动态端口>)         │
│  └─ token 认证 + 状态快照                     │
└─────────────────────────────────────────────┘
```

引擎在随机端口启动，把 `host/port/token/pid` 写入发现文件，壳读取后把 `baseUrl` + `token` 注入前端，避免端口冲突且前端零参数发现。

---

## 功能

- **三入口添加任务**：磁力链接、`.torrent` 文件、拖拽
- **任务管理**：暂停 / 继续 / 删除（含删除确认、文件占用时如实告知）
- **非法输入校验**：非磁力、重复添加、纯文本拖入等均有明确提示
- **健壮性**：引擎崩溃界面如实显示离线态；壳强杀后重开能接管孤儿引擎；任务加即落盘，每 30 秒补写
- **安装分发**：NSIS 安装包（currentUser 模式，不弹 UAC）

## 构建

### 引擎（C++，需 libtorrent 2.x）

引擎依赖 libtorrent 2.x，构建细节见 `engine/` 目录与 `specs/engine-service.md`。

### 前端 + 壳（需 Node.js + Rust）

```bash
cd desktop
npm ci          # 从锁文件复现安装（package-lock.json 已入库）
npm run build   # 前端构建
# Tauri 壳构建
cd src-tauri
cargo build --release
```

完整安装包构建见 `specs/installer.md`（NSIS 打包）。

## 安全说明（防投毒）

> **当前状态**：本项目尚未启用 commit/tag 的 GPG 签名，也未发布 Release 与 SHA-256 校验清单。
> 因此在启用前，请勿仅凭「仓库名」或「star 数」信任任何来源的副本。

Git 本身基于 SHA-256 内容寻址——任何一次提交的哈希都由其全部内容计算而来，篡改任意一个字节都会导致 commit 哈希改变。这意味着：**从本仓库官方地址 clone 到的历史，其每个 commit 哈希都是可独立校验的**。但请注意，这只保证「内容与官方仓库一致」，**无法识别**「恶意 fork 后注入代码、换个名字冒充本项目」的情形。

### 如何判断你拿到的副本可信

1. **核对远程地址**：确认你 clone 的来源是作者本人维护的仓库地址，而非名称相似的 fork。
2. **核对 commit 哈希**：与作者公布的 commit 哈希比对。
3. **审查代码**：对任何自称「本项目的二次分发/增强版」，务必逐文件审查 diff，确认没有夹带。

> **关于 MD5**：MD5 已被攻破（碰撞攻击），攻击者可构造「不同内容、相同 MD5」的文件绕过校验。任何声称「用 MD5 校验」来保证完整性的做法都不可靠，应改用 SHA-256。
